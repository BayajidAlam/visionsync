## Deployment Steps

### 1 — Install dependencies
```bash
make install
```

### 2 — Provision infrastructure
```bash
PULUMI_CONFIG_PASSPHRASE=<pass> make deploy
```
Runs `pulumi up`, then auto-calls `make save-outputs` + `make update-env`. After completion `.env.infra` has all live IPs and DNS names.

### 3 — Cache outputs (when passphrase unavailable)
```bash
# Get all EC2 IPs
aws ec2 describe-instances \
  --filters "Name=tag:Project,Values=vision-sync" \
  --query "Reservations[*].Instances[*].[Tags[?Key=='Name'].Value|[0],PublicIpAddress,PrivateIpAddress]" \
  --output table

# Get ALB DNS
aws elbv2 describe-load-balancers \
  --query "LoadBalancers[*].[LoadBalancerName,DNSName]" \
  --output table

# Get CloudFront domain
aws cloudfront list-distributions \
  --query "DistributionList.Items[*].[Id,DomainName,Status]" \
  --output table
```
Populate `.env.infra` manually, then continue from step 4.

### 4 — Set up databases
```bash
make ansible-bootstrap   # sync ansible + install on bastion + copy key
make setup-all-db        # MongoDB replica set + Redis
make check-mongodb       # verify: PRIMARY + 2 SECONDARY
make check-redis         # verify: PONG
```

### 5 — Update server environment
```bash
make update-env   # patches server/.env with current IPs from .env.infra / Pulumi
```

### 6 — Deploy application
```bash
make deploy-prod         # server + client
# or individually:
make deploy-server       # build Docker image → ECR → restart backend container
make deploy-client       # build client image on frontend EC2 (bakes VITE_CLOUDFRONT_URL)
make deploy-lambda       # build Lambda package + update function code (no Pulumi needed)
```

### 7 — Verify
```bash
make status-prod
curl http://<alb-dns>/api/webhook/health
# {"status":"ok","connections":0,...}
```

## Redis Setup: Docker vs Ansible

Redis runs in Docker on the EC2 instance. This was a deliberate choice over Ansible template provisioning:

**Ansible template approach (rejected):**
- 80+ line `redis.conf.j2` template
- 100+ line playbook with user creation, systemd service, directory structure
- Complex to maintain; difficult to version alongside infra

**Docker approach (current):**
```typescript
// IaC/src — userData baked into EC2 at launch
userData: `#!/bin/bash
yum update -y && yum install -y docker
systemctl start docker
docker run -d --name redis-server --restart unless-stopped \
  -p 6379:6379 -v redis-data:/data redis:7-alpine \
  redis-server --requirepass ${REDIS_PASSWORD} \
  --maxmemory 256mb --maxmemory-policy allkeys-lru \
  --save 900 1 --appendonly yes`
```

5 lines vs 100+. Redis restarts automatically. Data persists in named volume. Same result, far less complexity.

## Hard-Won Lessons

1. **`make deploy-server` fails without Pulumi passphrase** — `require-infra` calls `pulumi stack output` which needs `PULUMI_CONFIG_PASSPHRASE`. Fix: use `require-deploy` (reads `.env.infra`) and run `make save-outputs` once after each infra change.

2. **CloudFront domain changes on every redeploy** — After `make destroy` + `make deploy`, the CF distribution gets a new domain. Update `.env.infra` → `make deploy-client` to bake the new `VITE_CLOUDFRONT_URL=https://...` into the build. All DB-stored `manifestUrl` values become stale — always use `apiService.getManifestUrl(videoId)`.

3. **`VITE_CLOUDFRONT_URL` must include `https://`** — Makefile passes `--build-arg VITE_CLOUDFRONT_URL=https://$(CLOUDFRONT_DOMAIN)`. Without the scheme, dash.js receives a schemeless URL causing `ERR_NAME_NOT_RESOLVED`.

4. **CORS fails when client IP ≠ ALB URL** — `FRONTEND_URL` must be comma-separated: `http://<frontend-ec2-ip>,http://<alb-dns>`. A single value causes 403 for any other origin.

5. **`TRUST_PROXY=true` prod-only** — Enabling locally makes the rate limiter read `X-Forwarded-For` which can be spoofed. Omit from local `server/.env`.

6. **Lambda must NOT override `WEBHOOK_URL`** — ECS task definition has the correct ALB URL hardcoded. Overriding from Lambda env (which may be empty) causes the container to POST to empty string and silently fail.

7. **MongoDB replica set must be up before server starts** — Mongoose connection fails and the container exits if MongoDB isn't ready. Run `make check-mongodb` before `make deploy-server`.

8. **Double PROCESSING socket event** — `videoService.updateVideoStatus()` already emits the socket event. The `webhook.ts` else-branch must NOT call `socketService.emitVideoStatus()` again — doing so fires two events for every PROCESSING webhook.

9. **Rate limit key uses ALB IP without `TRUST_PROXY`** — All requests arrive from the ALB's private IP so every client shares one bucket. Always set `TRUST_PROXY=true` in production.

10. **ECS tasks need `assignPublicIp: DISABLED`** — Tasks run in private subnets behind NAT Gateway. `ENABLED` exposes the FFmpeg container directly to the internet and wastes an Elastic IP.

## Teardown

Empty S3 buckets first (Pulumi fails on non-empty buckets):
```bash
aws s3 rm s3://vision-sync-raw-videos-dev --recursive
aws s3 rm s3://vision-sync-processed-videos-dev --recursive
PULUMI_CONFIG_PASSPHRASE=<pass> make destroy
```

## Rollback

```bash
# List available ECR image digests
aws ecr describe-images \
  --repository-name vision-sync-server-dev \
  --query 'imageDetails[*].[imageTags,imagePushedAt]' \
  --output table

# SSH via bastion, restart with previous tag
ssh -J ubuntu@<bastion-ip> ubuntu@<backend-ip>
docker stop vision-sync-server && docker rm vision-sync-server
docker pull <ecr>:<previous-tag>
docker run -d --name vision-sync-server ... <ecr>:<previous-tag>
```
